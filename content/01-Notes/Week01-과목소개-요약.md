## 1. 이 과목에서 다루는 주안점

### 핵심 한 문장

> **ChatGPT, Claude, Gemini 같은 대형언어모델(LLM)을 "도구"로 다룰 줄 아는 건축공학 엔지니어를 양성한다.**

### 세 가지 주안점

#### ① 원리 이해 — "AI가 어떻게 작동하는가"
- Transformer 아키텍처, 토큰화, 컨텍스트 윈도우 등 LLM의 작동 원리를 이해한다.
- 환각(Hallucination), 지식 단절일 등 모델의 **한계**를 명확히 인식한다.
- 원리를 알아야 "언제 신뢰하고, 언제 검증해야 하는지" 판단할 수 있다.

#### ② 구현 역량 — "직접 만들 수 있는가"
- 프롬프트만 잘 쓰는 수준이 아니라, **Python + API로 시스템을 구축**하는 능력을 기른다.
- RAG, MCP, Agentic Workflow 등 최신 LLM 활용 아키텍처를 직접 코딩한다.
- Streamlit으로 데모 UI까지 구현하여 **작동하는 프로토타입**을 만든다.

#### ③ 건축공학 특화 — "우리 분야에서 쓸 수 있는가"
- 건설 문서 분석, BIM(IFC) 연동, 구조해석(Midas) 자동화, 파라메트릭 설계, 디지털 트윈 등 **건축공학 실무에 직접 적용**한다.
- 일반적인 AI 과목이 아니라, **건축공학 도메인 문제**를 LLM으로 해결하는 방법에 집중한다.

## 2. 왜 중요한가 — 필요성

### 건설산업의 현실

> [!question] 건축공학에서 AI가 왜 지금 중요한가?

- **문서 중심 산업**: 건설산업은 시방서, 법규, 계약서, 도면 등 방대한 텍스트·문서를 다루는 산업이다. LLM은 이 문서들을 읽고, 요약하고, 비교 분석하는 데 탁월하다.
- **반복적 검토 업무**: 법규 적합성 검토, 물량 산출, 보고서 작성 등 반복적이지만 전문 지식이 필요한 업무가 많다. LLM 기반 자동화로 생산성을 획기적으로 높일 수 있다.
- **데이터 연동 수요 급증**: BIM, IoT, 디지털 트윈의 확산으로, 이종 시스템 간 데이터를 연결하고 해석하는 인터페이스가 필요하다. LLM이 그 **자연어 인터페이스** 역할을 한다.

### AI 시대의 엔지니어 역량 변화

| 과거 역량 | AI 시대 추가 역량 |
|----------|-----------------|
| 수식·기준 이해 | + **AI에게 올바른 질문**을 하는 능력 |
| 수작업 계산·검토 | + **자동화 시스템을 설계·구축**하는 능력 |
| 소프트웨어 사용자 | + **AI 도구를 직접 만드는** 개발 역량 |
| 보고서 작성 | + **AI가 생성한 결과를 검증**하는 판단력 |

### 지금이 적기인 이유

- **LLM API의 보편화**: Claude, GPT, Gemini 등 고성능 모델을 API로 누구나 활용 가능
- **MCP 표준의 등장**: Model Context Protocol로 LLM과 외부 도구(BIM, 구조해석 등)를 표준 방식으로 연결
- **비용 현실화**: 모델 티어링, Prompt Caching 등으로 대학원생도 경제적으로 활용 가능
- **AI 코딩 도구 발전**: Cursor, Claude Code 등으로 프로토타이핑 속도가 비약적으로 향상

### 기초 → 응용 연계

| 기초 기술 (1-7주)                 | →   | 응용 시스템 (9-13주)           |
| ---------------------------- | --- | ------------------------ |
| VS Code, GitHub, AI 코딩 도구    | →   | 코드 관리, 협업, 프로젝트 배포       |
| REST API, FastAPI, Streamlit | →   | 디지털 트윈 서버, IoT 연동, 데모 UI |
| LLM API (Streaming, 비용 관리)   | →   | 모든 응용 시스템의 핵심 엔진         |
| RAG + 평가                     | →   | 건설 문서 분석, 법규 검토          |
| MCP + Agentic Workflow + 보안  | →   | BIM 연동, 구조해석 연동          |

### 프로젝트 기반 평가

| 구분      | 시기      |   비중    | 내용                                     |
| ------- | ------- | :-----: | -------------------------------------- |
| 주차별 과제  | 매주      | **40%** | 해당 주 기술을 적용한 코드 구현                     |
| 중간 프로젝트 | 8주차     | **25%** | Agentic Workflow 시스템 (RAG/MCP + 데모 UI) |
| 팀 프로젝트  | 14-15주차 | **25%** | 2-3인 팀, 전체 기술 통합, 건축공학 실무 시스템          |
| 참여도     | 상시      | **10%** | 수업 참여, 동료 평가                           |

> [!action] 핵심 원칙
> 모든 과제와 프로젝트는 **"작동하는 코드"** 와 **"데모"** 를 요구한다. 이론 보고서가 아니라, 실제로 실행되는 시스템을 만든다.

## 5. 수강 후 할 수 있는 일

### 즉시 적용 가능한 역량

#### 🔧 건설 문서 자동화
- 시방서·법규를 RAG 시스템에 넣고 자연어로 질의응답
- 계약서 비교, 설계 기준 검토를 LLM으로 자동화
- **예**: "이 프로젝트에 적용되는 내진설계 기준을 정리해줘" → 자동 추출·요약

#### 🏗️ BIM + AI 연동 시스템 구축
- IFC 모델에서 물량을 자연어로 질의: "3층 벽체 총 콘크리트 체적은?"
- BIM 데이터를 MCP로 연결하여 Claude/ChatGPT에서 직접 조회
- **예**: BIM 물량 산출 AI 어시스턴트

#### 📐 구조해석 결과 자동 분석
- Midas 해석 결과에서 위험 부재를 자동 탐지하고 보고서 생성
- 자연어로 모델 정보 조회: "최대 모멘트가 발생하는 보 10개를 알려줘"
- **예**: 구조 설계 검토 자동화 도구

#### 🏢 디지털 트윈 지능화
- IoT 센서 데이터 + LLM으로 건물 상태 실시간 모니터링
- 이상 징후를 자연어로 보고: "2층 사무실 CO₂가 기준치를 초과했습니다"
- **예**: 스마트 빌딩 운영 AI 플랫폼

#### 🎨 자연어 기반 설계
- "남향 채광 최대화, 건폐율 60% 이내" → Grasshopper 파라미터 자동 생성
- 설계 의도를 자연어로 입력하면 파라메트릭 스크립트가 생성
- **예**: 자연어 → 건축 매스 자동 생성
